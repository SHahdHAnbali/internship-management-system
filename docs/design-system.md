# IMS Design System

Source: the official visual reference (a clean, white corporate site with an orange accent). Only its **visual style** is used. Its content and navigation are not.
Every page must use these tokens and utilities instead of raw values.

## Styling approach

| Layer | File | Used for |
|---|---|---|
| **Tailwind CSS v4** (primary) | `src/tailwind.css` (via `@tailwindcss/postcss`, `.postcssrc.json`) | Layout, spacing, sizing, responsiveness, typography and colours **in templates**. The `@theme` block maps the IMS tokens into Tailwind, and `@layer components` holds the few named design-system classes |
| **SCSS: tokens** | `src/styles/_tokens.scss` | The single source of the design tokens (`--ims-*` CSS variables). Tailwind and Material both read them |
| **SCSS: base** | `src/styles/_base.scss` | Element defaults (body, headings, links, focus, selection) inside Tailwind's `@layer base`, after Tailwind's preflight reset |
| **SCSS: Material theme** | `src/styles.scss`, `src/styles/_theme-colors.scss` | Angular Material M3 theme, system-token pins and component overrides (`mat.*-overrides`) |
| **SCSS: complex custom styles** | `src/styles/_components.scss`, component `.scss` | Overrides of Material internals that utilities cannot express (e.g. `.ims-table-card`, `.language-button`) |

**Cascade.** Tailwind declares `@layer theme, base, components, utilities`. Angular Material's CSS and the SCSS overrides are *unlayered*, so they beat Tailwind layers. Consequences:
- Put utilities on **your own elements** for layout and spacing (`flex`, `gap-4`, `px-gutter`, `max-w-content`).
- On a Material component's host, a utility wins only for properties Material doesn't set itself (width, margin, order). To override a property Material sets (colours, padding inside dialogs…), use the `!` suffix (`pt-2!`) or an SCSS override.
- Element base styles live in `@layer base`, so a utility such as `text-h2` on an `<h1>` works.

**Tailwind theme (from `@theme inline` in `src/tailwind.css`)**
- Colours, **only** the IMS palette (Tailwind's default colour scales are removed): `brand`, `primary`, `primary-hover`, `primary-soft`, `heading`, `body`, `muted`, `border`, `divider`, `surface`, `surface-subtle`, `white`. Use them as `text-heading`, `bg-surface`, `border-border`, `bg-brand`, and so on.
- Type sizes: `text-display`, `text-h1`, `text-h2`, `text-h3`, `text-body`, `text-small`. Font: `font-sans` = `--ims-font-sans`.
- Radius: `rounded-control` (10px), `rounded-card` (16px). Shadow: `shadow-card`, `shadow-raised`.
- Layout: `max-w-content` (1200px), `px-gutter` (fluid 16–32px), `min-h-header` (64px).
- Spacing: Tailwind's default 4px scale (`p-4` = 16px, `gap-6` = 24px, …), the same base as `--ims-space-*`.
- Breakpoints: Tailwind defaults (`sm` 640px, `md` 768px, `lg` 1024px, …) plus `nav` (900px), where the app header switches from two rows to one.
- RTL/LTR: use logical utilities (`ms-*`/`me-*`, `ps-*`/`pe-*`, `start-*`/`end-*`, `border-s`, `text-start`) and never `ml-*`, `mr-*`, `left-*` or `right-*`.

## Character
White surfaces, generous whitespace, dark, bold, tightly-tracked headings, gray body text, hairline borders instead of shadows, and **one** warm orange accent used sparingly for the active state, primary action and highlights.

## Colour tokens (`styles/_tokens.scss`)

| Token | Value | Use |
|---|---|---|
| `--ims-color-brand` | `#E64D20` | Accent sampled from the reference: active nav underline, focus ring, highlights (`.ims-accent`), decorative icons |
| `--ims-color-primary` | `#C93D12` | Interactive colour: filled buttons, links, active nav text, toggles. A slightly deeper shade of the brand orange, chosen because white text on `#E64D20` is only 3.86:1. `#C93D12` passes WCAG AA both ways (5.05:1) |
| `--ims-color-primary-soft` | `#FFF1EC` | Tinted background for the selected or current item (badge, language switch) |
| `--ims-color-heading` | `#0F1217` | Headings, strong text |
| `--ims-color-text` | `#474A4D` | Body and navigation text |
| `--ims-color-text-muted` | `#6B6F78` | Secondary text, table headers, hints |
| `--ims-color-border` | `#E7E7EA` | Card and control borders |
| `--ims-color-divider` | `#EEEEEE` | Header bottom line, table row lines |
| `--ims-color-bg` / `--ims-color-surface` | `#FFFFFF` | Page and card background |
| `--ims-color-surface-subtle` | `#FAFAFB` | Table header, row hover |

Angular Material's M3 system tokens (`--mat-sys-*`) are pinned to these values in `styles.scss` through `mat.theme-overrides`. The tonal palettes in `styles/_theme-colors.scss` were generated by `ng generate @angular/material:theme-color` from `#E64D20` and `#6B6F78`. Material components therefore match automatically.

## Typography
- **Font:** Inter (Latin). Arabic glyphs fall back to Noto Sans Arabic. Both are loaded from Google Fonts in `index.html`. Token: `--ims-font-sans`.
- **Scale:** display `clamp(2rem…3rem)`, h1 `clamp(1.625rem…2.125rem)` weight 700 tracking −0.02em, h2 1.375rem/700, h3 1.0625rem/600, body 0.9375rem/1.6, small 0.8125rem.
- Use `h1.ims-page-title` once per page. Card and section titles use `h2`/`h3`.

## Shape, spacing, elevation
- **Radius:** controls and buttons `10px` (`--ims-radius-md`), cards, dialogs and tables `16px` (`--ims-radius-lg`), badges pill.
- **Spacing:** 4px scale `--ims-space-1…8` (4, 8, 12, 16, 24, 32, 48, 64). Page side padding is `--ims-gutter` (16–32px, fluid).
- **Elevation:** borders first. `--ims-shadow-card` is a barely visible 1px shadow; `--ims-shadow-raised` is for overlays only.
- **Content width:** `--ims-content-max-width` (1200px), centred.

## Reusable patterns

**Design-system classes** (Tailwind `@layer components` in `src/tailwind.css`):

| Class | Purpose |
|---|---|
| `.ims-page-title` | Page `h1`: `text-h1 font-bold tracking-[-0.02em] text-heading` |
| `.ims-card` | Bordered white card: `rounded-card border border-border bg-surface p-6 shadow-card` |
| `.ims-state` | Empty, error or loading message: dashed border, muted, centred |
| `.ims-badge` | Small pill label: `bg-primary-soft text-primary` |

**SCSS classes** (Material internals):

| Class | Purpose |
|---|---|
| `.ims-table-card` (`styles/_components.scss`) | Card wrapping a `mat-table`: subtle header row, row hover, cell padding, horizontal scroll on small screens |
| `.ims-dense` (`styles.scss`) | Compact 40px form field for controls inside table rows |

## Component defaults
- **Form fields:** `outline` appearance app-wide (`MAT_FORM_FIELD_DEFAULT_OPTIONS` in `app.config.ts`), 10px radius.
- **Buttons:** `mat-flat-button` for the single primary action, `mat-button` for secondary actions. Labels weight 600.
- **Tabs:** no divider; active = primary text + brand underline.
- **Dialogs:** 16px radius, white. **Snack bars:** dark (`#0F1217`), 10px radius.

## Rules
1. Style with Tailwind utilities in templates first. Use SCSS only for tokens, the Material theme, and overrides of Material internals. Don't add component `.scss` files for layout or spacing.
2. Never hard-code colours, radii or spacing. Use the theme utilities (`text-heading`, `rounded-card`, `p-6`) or `var(--ims-…)` / `--mat-sys-*` in SCSS. Arbitrary values (`max-w-[520px]`) are for one-off sizes only, never for colours.
3. Use logical properties and utilities only, so RTL and LTR both work.
4. Use one primary (filled) button per view. The orange accent is for state and emphasis, not for decoration.
5. New areas (trainee, employee, HR) reuse the header and page recipes above (see `features/admin/layout/admin-layout.html`).
6. Add a class to `@layer components` only for a named, repeated design-system pattern. Otherwise compose utilities.
7. Check every page at 390px width and in both Arabic and English.
